# `@oneirodex/ui` — deferred work

Wave **B1.2** consolidated the duplicated _infrastructure_ modules into this
package (see `src/`): `confirmDialog`, `libraryScanNotify`, `toastStack`,
`useRailState`, `csrf`, `envelopeError`, `loadingStatusText`, `pageStatus`
(+ `resolveErrorMessage` / `resolveErrorDetail`). Every SPA consumer imports
`@oneirodex/ui`; the dead per-app copies are gone; contract tests live in
`src/*.test.*` and run via `npm test --workspace=frontend/shared`.

The following were **out of scope for B1.2** and are tracked here.

## Module consolidations still to do

### `showToast` (`utils/toast.js`) — mechanical, deferred for test churn

`@oneirodex/ui/toast.js` (`showToast`) is the canonical copy and is already
exported from the barrel. The member and admin `src/utils/toast.js` copies are
**identical except one doc-comment line**, so this is a safe merge — but ~25
consumers plus ~10 test files that do `vi.mock('../utils/toast', …)` /
`vi.mock('./utils/toast', …)` still point at the per-app file. Each `vi.mock`
must become
`vi.mock('@oneirodex/ui', async (io) => ({ ...(await io()), showToast: vi.fn() }))`
so mocking toast does not blank the rest of the barrel (`confirmAction`,
`PageStatus`, `csrfHeaders`, `groupLibraryScanToasts`…). Do it as one commit.

### `platformSkins.js` — genuine divergence, needs art/chrome review

- member (`chrome/platformSkins.js`): drives `data-platform` / `-family` /
  `-motion` chrome — `applyPlatformSkin`, `clearPlatformSkin`, `sharedPlatform`,
  `familyForPlatform`; `FAMILY_META` carries a `motion` field.
- admin (`platformSkins.js`): Art-Studio-preview only — `ART_STUDIO_SYSTEMS`,
  `systemLabel`; no motion; `pc` accent differs (`#2fd67b` vs `''`);
  `skinForPlatform(unknown)` falls back to `pc` instead of returning `null`.

A superset merge changes admin's `skinForPlatform` null-semantics. Needs the art
seat to confirm the merged `FAMILY_META` + fallback behaviour.

### `railIcons.jsx` — two deliberate icon sets, art decision

member uses filled-accent glyphs; admin uses stroke-only glyphs and its own
header comment says it is generated by the same script "rather than shared via
frontend/shared, which … broke the image build once already". The Dockerfile is
workspace-aware now so that constraint is lifted, but picking one icon set is an
art-direction call, not a mechanical consolidation.

### `OpenPathModal.jsx` — divergence, needs desktop/backend confirm

member: `queueClientCommand` + `showToast` + portal + `clientConnected` /
`gameUuid` props + body-scroll-lock. admin: `postJson('/api/client/commands')`
directly, fewer props, no portal. Unifying means admin adopts the member
companion-queue flow — confirm with the desktop/backend seats first.
