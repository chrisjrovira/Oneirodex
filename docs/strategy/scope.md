# Scope

Public strategy docs describe **what we are building and why**.

They no longer carry `Explicit non-goals` / `Out of scope` sections declaring
what will never be built. Those read as commitments to anyone browsing the
repo, and they were being quoted back during planning as if settled when most
were only ever "not this quarter". Reversing one then looks like a retreat
rather than an ordinary change of plan.

**Anything not described in a public doc is unscheduled, not refused.**

The working list — what we have chosen not to build yet, the reasoning at the
time, and the conditions that would change it — lives in the private vault:

```
docs/_private/scope-decisions.md
```

Same arrangement as [competitive.md](competitive.md): the decisions are real and
written down, they just are not a public promise.

Per-feature docs still use **"Not in this slice"** to bound a particular piece
of work. That is scheduling for one slice, not a product-level refusal.
